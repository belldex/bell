# BELL Integration Pack

**Network:** Robinhood Chain Mainnet · chain ID `4663`
**Status:** BELL protocol contracts, the updated Worker, and six per-pool Lens contracts are deployed. All six Lens instances have an exact Sourcify source match. Third-party integration acceptance is not established.
**Updated:** 10 November 2026

This pack is for wallets, terminals, aggregators and indexers integrating BELL pools. It is a data and routing guide, not a promise that a pool has liquidity, that a quote will execute, or that a third party has accepted an integration.

## Live data

The BELL keeper serves a public JSON pool directory:

```text
GET https://bell-keeper-b.asysyifaq25.workers.dev/pools
```

The response includes `chainId`, `blockNumber`, pool IDs, token addresses and symbols, hook addresses, policy state, current pool liquidity, auction binding, and the per-pool Lens address when registered. If the binding read fails, `hasAuction` is `null` (unknown). Treat the live endpoint as the current discovery source; a committed pool list is only a dated snapshot.

Read a pool's indexed receipts with newest-first cursor pagination:

```text
GET https://bell-keeper-b.asysyifaq25.workers.dev/pools/{poolId}/receipts?limit=50
```

The response includes `Initialize`, `Swap` (including the fee field), and auction receipts with block number/hash, transaction hash, log index, decoded event arguments, and Blockscout links. `nextCursor` continues the pinned scan window. The endpoint uses bounded log windows and may return a clear unavailable response if a window exceeds the indexer's safety bound.

## Check policy before routing

Obtain the pool's hook and Lens address from `/pools` and ask the Lens whether the exact input and direction are allowed:

```text
GET https://bell-keeper-b.asysyifaq25.workers.dev/pools/{poolId}/status?zeroForOne=true&amountIn={raw-uint256}
```

The returned `status` contains:

| Field | Meaning |
| --- | --- |
| `allowed` | Whether the Lens accepts this exact-input quote against the policy and pool state it read. |
| `reason` | The custom-error selector that explains a blocked result; `0x00000000` means no BELL policy error. |
| `session` | `0 UNKNOWN`, `1 PRE`, `2 REGULAR`, `3 POST`, `4 OVERNIGHT`, `5 CLOSED`. |
| `currentFeePips` | Current hook fee in Uniswap fee units; zero means the fee could not be read. |
| `maxIn0`, `maxIn1` | Remaining gross flow budgets in raw token units. A swap can still hit the other side's budget or price-path constraints. |
| `auctionWindow` | True while the bound auction is accepting orders. The auction can also block swaps while it is locked for settlement. |
| `nextTransition` | Unix timestamp of the next calendar transition, or zero if unavailable. |

Example:

```ts
const params = new URLSearchParams({ zeroForOne: 'true', amountIn: rawAmount.toString() });
const response = await fetch(`https://bell-keeper-b.asysyifaq25.workers.dev/pools/${poolId}/status?${params}`);
const { status, blockNumber, lens } = await response.json();
if (!status.allowed) {
  // Surface the returned reason and refresh the quote; do not route the swap.
}
```

`BellSwapLens` instances are immutable and bound to one hook/pool. A new pool needs its Lens address recorded in the pool directory before the status endpoint can answer for it. If no Lens is registered, the endpoint returns an explicit not-found response rather than guessing.

## Routing and hook data

The production router is `BellRouter` at [`0x178d78419e8b7cd1f5e1e4a65f71d86c7f6516d5`](https://robinhoodchain.blockscout.com/address/0x178d78419e8b7cd1f5e1e4a65f71d86c7f6516d5). It validates the pool binding, request deadline/config hash, quote envelope and flow limits before the PoolManager swap.

The hook source accepts empty `hookData` for an ordinary swap; non-empty data is used for encoded oracle updates. A Universal Router rehearsal with empty hook data remains **PLANNED / NOT VERIFIED**: no successful receipt is recorded, so source-level support alone does not establish end-to-end router compatibility.

## Fees and sessions

Use the fee in the PoolManager `Swap` event for a transaction that actually occurred. The current snapshot is [generated by `pnpm verify:bell`](../../apps/web/content/mainnet-verification.json); each event links to its transaction and carries the session label read from the hook policy at that block. A session without a successful Swap event is shown as unobserved, not filled with an expected fee.

The verified policy source defines base fee values, but effective fee may include pool-specific policy or transition logic. For a live quote, use `getSwapStatus`; for historical execution, use the event's `fee` field.

## Opening Bell Auction

An auction is pool-specific and write-once. Discover it from `hasAuction`/`auction` in `/pools`, then read the live stage and cycle through:

```text
GET https://bell-keeper-b.asysyifaq25.workers.dev/auctions?pools={poolId}
```

The response reports the bound auction, stage, `blocksSwaps`, cycle, open time, auction lead and settlement information when available. Ordinary AMM swaps and liquidity additions are blocked only in the states enforced by the deployed auction/hook. Unmatched orders are handled by the auction's settlement/refund rules; a UI should not infer fills from order submission.

## Custom errors

| Error | Meaning | Source |
| --- | --- | --- |
| `AuctionActive()` | The pool's bound auction currently blocks the swap callback. | [`BellHookV2.sol`](../../contracts/src/BellHookV2.sol) |
| `PolicyBlocked(uint256)` | Session, health, anchor, pause, or another policy input blocks the swap. | [`BellPolicyOracle.sol`](../../contracts/src/BellPolicyOracle.sol) |
| `TradeCapExceeded(uint8,uint256,uint256)` | The exact input/delta exceeds the per-trade gross budget. | [`FlowBudget.sol`](../../contracts/src/libraries/FlowBudget.sol) |
| `WindowCapExceeded(uint8,uint256,uint256)` | The rolling-window gross budget is exhausted. | [`FlowBudget.sol`](../../contracts/src/libraries/FlowBudget.sol) |

Decode error selectors from the ABI shipped with the source, not from a hand-maintained selector table. The Lens returns the selector in `reason` and the receipt endpoint retains the actual mined event/transaction evidence.
