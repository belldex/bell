# Security Invariants and Evidence

| Invariant | Security property | Existing evidence to review |
| --- | --- | --- |
| LP exit cannot be blocked by BELL policy | The hook never receives `beforeRemoveLiquidity` or `afterRemoveLiquidity` permissions; removal proceeds through the v4 PositionManager. | `contracts/test/unit/hook/BellHook.t.sol::testHookPermissionsAreExactAndReturnDeltaFlagsAreFalse`; `contracts/test/integration/public-lp/PublicPositionManager.t.sol`; `contracts/test/invariant/exit/ExitLivenessFuzz.t.sol`; `scripts/verify-exit-liveness.ts`. |
| Escrowed auction funds are settleable or refundable | A cycle finalizes once; claims are owner-bound; unmatched inputs are recorded as refunds; timeout refund prevents escrow from remaining locked after the cycle deadline. | `contracts/test/BellOpeningAuction.t.sol` (unfilled buyer, below-clearing-price, timeout refund); `contracts/test/BellAuctionRegistry.t.sol`; `contracts/test/integration/factory/LossOfFundsIndex.t.sol`. |
| Auction pool binding is immutable in practice | The registry writer is set once by the factory; each pool auction mapping can be written once by the authorized module. | `contracts/test/BellAuctionRegistry.t.sol::testFactorySetsWriterOnceAndWriterBinds`, `testOnlyWriterCanBindAndCannotRebind`, `testPoolBindingsAreIndependent`. |
| No proxy can replace deployed logic | Mainnet contracts are direct deployments; no upgrade proxy or implementation-admin path is part of the BELL deployment. | Mainnet bytecode/address manifests, verification records, constructor and permission review. Confirm every in-scope address at the frozen commit. |
| Missing/stale policy inputs fail closed | Invalid dependencies, calendars, health, or close anchors produce blocking policy reasons rather than a healthy fallback, except for explicitly configured price-protection fallback behavior. | `contracts/src/BellPolicyOracle.sol`; `contracts/test/unit/hook/BellHookClosure.t.sol`; `contracts/test/integration/swaps/CoreSwapPolicy.t.sol`; `LossOfFundsIndex.t.sol`. |
| Flow limits use actual PoolManager deltas | Both token sides are charged from actual deltas; trade, rolling-window, and closure budgets are checked before writes. | `contracts/src/libraries/FlowBudget.sol`; `contracts/test/integration/swaps/BellSwapEvaluator.t.sol`; `LossOfFundsIndex.t.sol`. |
| A failed swap cannot consume a budget | PoolManager and hook callback revert atomically; accounting writes do not persist on a reverted swap. | Hook/evaluator integration tests and Mainnet reverted `TradeCapExceeded` receipt in [`deployments/rule-tests.json`](../../deployments/rule-tests.json). |
| Lens cannot mutate or bypass policy | Each Lens is immutable, has no storage slots, owner, or proxy, and only reads a single bound hook/pool. | `BellSwapLens.t.sol`; storage layout output recorded in the implementation report; deployed bytecode and full-match verification to be added at release. |
| Lens status is scoped to a supported quote | `getSwapStatus` simulates exact input with empty hook data and full-range standard price limits. It does not attest payer balance, allowance, router slippage, or nonstandard price limits. | `contracts/test/integration/verification/BellSwapLens.t.sol`; [integration pack](../integrations/README.md). |

The `LossOfFundsIndex.t.sol` suite maps threat scenarios to behavior but is an internal test index, not an independent audit or formal proof. The auditor should independently validate each invariant, all reachable states, and assumptions about external contracts.
